# study-cafe 구현 계획

2026-10-13 · 설계 v0.1의 구현 계획. 현재 백엔드 구현 범위와 검증 결과는 [백엔드 가이드](BACKEND.md)와 [검증 기록](VERIFICATION.md)를 따른다. 아래 단계표는 원래 계획이며 프론트엔드는 보류 중이다.

## 개발 순서

단계마다 동작을 확인한 뒤 다음 단계로 확장한다. 임시 응답으로 만든 화면과 실제 코덱스 호출을 구분해 기록한다. P0~P4를 통과해야 첫 통합 버전으로 부른다.

| 단계 | 만들 것 | 완료 조건 |
|---|---|---|
| P0 연결·기술 확인 | Windows에서 Codex 어댑터, 지원 인증·검색·자료 읽기, 버전 고정, SQLite·복습 라이브러리 검토 | 실제 구조화 응답 1회, 이벤트·실패·취소 확인. 토큰 복사 없이 지원 인증 사용. 한국어·일본어 저장·검색과 DB 마이그레이션 확인 |
| P1 목표·시험 기본 기능 | 로컬 앱 실행, 목표·범위·템플릿, 25문항 시험·답안·객관식 채점, 백업·복원 | 통제된 예제로 정확한 유형·수량, 새로고침·재시작 후 이어 풀기, 중복 제출·저장 충돌 처리, 복원 후 동일 기록 |
| P2 자료·문제은행 | 조사 작업, URL·텍스트 PDF·직접 입력, 출처·근거 구간·자료 묶음·중복·검토 상태 | 실제 수집 가능한 자료로 원문부터 문항까지 추적, 수집 불가·정답 불명·필수 첨부 누락 분리, 저장 단계 재개 |
| P3 에이전트 출제 | 범위 구체화, 구성표, 기존 문항 선택, 부족분 생성·검토, 진행 화면 | 실제 에이전트로 객관식 20 + 주관식 5 완성, 범위·근거·유형·합계 검사, 중간 실패 시 해당 슬롯 재개 |
| P4 평가·학습 순환 | 기준별 주관식 평가, 재검토, 개념별 오답, 복습 일정·변형, 다음 학습 | 실제 답안으로 평가·보류·수정·일정 검증, 원본/변형/힌트 노출 분리, 전체 25문항 학습 순환 수행 |
| P5 자료·시험 확장 | 스캔 PDF OCR, 표·수식, 음성 지문, 실행 검증, 공식 형식 모의시험, 설치 편의 | 각 지원 기능별 실제 자료 확인. 음성 없이 청해 완료로 처리하지 않음. 시험별 형식·범위 근거 확보 |

P0에서 지원이 확인되지 않은 연결 기능은 확정 기능으로 표시하지 않는다. 특히 로컬 앱이라는 이유로 오프라인 모델 추론이 가능하다고 가정하지 않는다. 사용 가능한 계정·호출 한도·버전에서 실제 요청을 확인한다.

## 첫 구현 단위

첫 개발 작업은 **P0 연결 검증과 P1의 작은 종단 흐름**으로 잡는다.

1. 설치된 Node·Codex 버전과 실행 경로를 확인한다.
2. 앱 서버 초기화·계정 상태·짧은 구조화 요청·취소를 검증하고 어댑터 계약을 고정한다.
3. 목표 하나를 SQLite에 저장하고 브라우저에 다시 불러온다.
4. 시험 템플릿과 25문항 예제를 저장하고 한 문항의 답안을 서버에 저장한다.
5. 재실행 후 목표·시험·답안이 복구되는지 확인한다.

예제는 `개발용 예제`로 표시한다. 이 단계에서 AI 출제·기출 수집·주관식 평가까지 완료했다고 표시하지 않는다. 서버 시작 명령과 설치법은 실행 가능한 코드가 생긴 뒤 README에 추가한다.

## 집중 검증 사례

- **시험 수량:** 기출만 25개 요청에 17개만 가능하면 부족 8 표시. 승인 없이 AI로 채우거나 수량을 줄이지 않는다.
- **유형 합계:** 객관식 20 + 주관식 5를 지키고, 독해 지문 하나에 딸린 여러 문항도 정확히 센다.
- **작업 복구:** 18/25 확정 후 중단·재실행. 확정 결과는 유지하고, 재호출·늦은 응답으로 문항이 중복되지 않는다.
- **저장·제출:** 두 탭 수정, 재연결, 제출 재요청에서 답안이 유실·중복 확정되지 않는다.
- **시간:** 일반 학습의 정지와 실전 종료 시각을 분리한다. 서버 중단 중 만료도 확인한다.
- **채점 실패:** 잘못된 JSON·응답 없음·필수 근거 부족은 보류. 임의 절반 점수·0점으로 확정하지 않는다.
- **재채점:** 정답 수정 후 총점·개념 상태·복습 상태가 유효 평가로 다시 계산되고 새 성공 횟수가 생기지 않는다.
- **복습:** 부분 정답과 회상 난이도를 구분한다. 같은 날 힌트 직후 성공·새 변형 성공·원본 재풀이를 별도로 보존한다.
- **자료 안전성:** 웹 문서의 실행 지시를 자료로 취급한다. 내부 URL 접근·실행 HTML·토큰 로그 유출을 막는다.
- **백업:** DB와 첨부의 일관성을 검사하고 다른 데이터 디렉터리에 복원해 동일 시험·답안·근거를 연다.

규칙·저장 경계는 자동 테스트로, 에이전트 출력 품질과 자료 근거는 실제 예제 검토로 확인한다. 실제 호출 비용과 변동성을 줄이기 위해 실패 재현에는 저장된 비밀 없는 fixture를 사용한다. 실제 연결 검증을 fixture 테스트로 대체하지 않는다.

## 구현 전에 고정할 제안값

아래 값은 사용자 요구를 해석한 초기 제안이며 구현·검증 중 조정할 수 있다.

| 항목 | 초기 제안 |
|---|---|
| 일반 회차 | 25문항, 객관식 20 + 짧은 주관식 5 |
| 출처 정책 | 기존 자료와 AI 혼합, 구성 전 비율 표시 |
| 조사 예산 | 30개 후보 URL 또는 10분, 이어서 확장 가능 |
| 작업 동시성 | AI 작업 1개, 완료된 문항부터 단계 저장 |
| 사용자 환경 | 개인 PC, 한국어 UI, 변경 가능한 Asia/Seoul 시간대 |
| 초기 자료 | 웹·텍스트 PDF·사용자 텍스트, 첨부가 필요한 문항은 지원 여부 확인 |
| 복습 | 개별 항목 스케줄과 개념별 근거를 분리, FSRS 계열 구현체 검토 |
| 실행 구조 | React·TypeScript, Node·Fastify, SQLite, Codex 어댑터 |

기간은 P0에서 연결·자료 추출의 실제 제약을 확인한 뒤 산정한다. 구현 순서는 유지하되 청해·OCR·복잡한 수식 등 목표에 꼭 필요한 지원은 해당 목표를 제공하기 전에 완료한다.

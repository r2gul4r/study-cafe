# study-cafe 프론트엔드

React 19 + TypeScript + Vite. 사용자 화면은 한국어이며 무료 템플릿의 레이아웃 패턴을 참고해 기존 REST API에 맞게 구현했다.

## 실행

Windows: 저장소에서 `.\scripts\start.ps1`. 백엔드와 프론트를 빌드한 뒤 http://127.0.0.1:4317 에서 제공한다.

일반 환경: `pnpm install --frozen-lockfile`, `pnpm --dir apps/web install --frozen-lockfile`, `pnpm build`, `pnpm start`.

처음 연결할 때 서버가 안내하는 데이터 디렉터리의 `session-token` 내용을 입력한다. OpenAI API 키가 아니다. 토큰은 sessionStorage에 저장하며 로그아웃하면 제거한다. 실제 데이터는 SQLite와 로컬 첨부 폴더에 저장한다.

개발: `pnpm dev`와 `pnpm dev:web`을 각각 실행. 5173의 Vite가 `/api`와 `/health`를 4317로 프록시한다. 사용자 지정 포트는 Vite 설정과 허용 Origin을 함께 맞춘다.

## 데이터 보존과 오류 처리

- 자동 저장은 문항별로 직렬화한다. 답안 버전 충돌 시 서버 답안과 현재 답안을 사용자가 선택한다.
- 저장되지 않은 답안은 탭 세션에 임시 보관한다. 새로고침 시 서버 버전과 비교하고 복구한다. 서버에 저장하지 못한 상태에서는 제출·일시정지를 막는다.
- 제출 요청 ID를 탭에 보관해 네트워크 재시도에도 같은 제출로 처리한다.
- 확정 점수와 보류 문항 수를 분리한다. 채점 실패를 0점으로 표시하지 않는다.
- API는 계속 Bearer 토큰·Host·Origin 검사를 적용한다. 공개 정적 경로는 빌드된 HTML·assets이며 학습 데이터 API와 분리한다.
- 정적 HTML은 캐시하지 않고 CSP·nosniff를 적용한다. 외부 URL은 http/https만 링크로 허용한다.

## 디자인·비용

Shadcn Admin의 탐색/목록과 Shadcn Dashboard의 노트 구성을 참고했다. 색상·한글 타이포그래피·컴포넌트·상태 처리는 study-cafe용으로 구현했다. 유료 템플릿, 21st 생성 호출, 결제 코드, 외부 폰트 CDN을 사용하지 않는다. 자세한 출처는 `apps/web/THIRD_PARTY_NOTICES.md`.

AI 요청은 기존 로컬 Codex 백엔드에 전달된다. 별도 API 키나 유료 대체 공급자를 추가하지 않았다. 실제 AI 이용은 로그인한 Codex 계정 한도의 영향을 받는다.

## 검증 방법과 범위

- `pnpm check`: 백엔드·프론트 타입 검사와 테스트.
- `pnpm build`: 두 앱의 프로덕션 빌드.
- `node --import tsx scripts/ui-fixture.ts`: 임시 디렉터리에만 검증 데이터를 만들고 4319에서 제공. 연결 토큰 `study-cafe-ui-only`. 외부 AI는 호출하지 않으며 오류 경로를 검증한다. 운영 데이터 디렉터리는 읽지 않는다.
- 브라우저 검증: 목표 생성/선택, 범위 저장, 텍스트 자료 수집, 25문항 시작, 객관식·주관식 저장, 표시 보존, 일시정지/재개, 답안 충돌 해결, 제출/채점 보류/수동 확정, 문제 필터, 노트·복습·작업·모바일 탐색.

2026-10-14 추가 검증: 정상 PDF와 손상된 PDF를 브라우저 파일 선택기로 업로드하고 추출 본문·작업 실패 이유를 확인했다. 문항 편집·주관식 배점 합계 오류·새 버전 저장·이전 버전 조회·동시 수정 충돌 해결·검토 확정·과거 재채점·정정된 해설 표시를 확인했다. 390px 모바일 편집 모달의 가로 넘침도 확인했다.

실제 Codex로 Python 목표 설계·공식 참고 자료 조사/수집·25문항 응시·채점(34/39점, 보류 0)·오답 요약·변형·복습 일정까지 브라우저에서 확인했다. API 검사와 구분한 상세 결과는 [VERIFICATION.md](VERIFICATION.md)에 기록한다. 실제 자격시험 기출 확보, OCR·코드 실행 채점·청해 전용 플레이어는 후속 범위이며 첨부는 내려받아 확인한다. 백업 복원은 CLI 기능이며 별도 화면은 아직 없다.

목표는 한 번에 하나만 펼쳐지고 선택한 행 바로 아래에 상세가 나온다. 각 행의 `⋯`에서 수정·보관·복원·영구 삭제를 선택한다. 영구 삭제는 관련 기록 수와 유지되는 공용 첨부·템플릿·백업을 안내하고 목표 이름을 확인한다. 대기/실행 중인 작업이 있으면 먼저 완료 또는 취소해야 한다. 확인 후 기록이 바뀌면 삭제 창을 다시 열어 범위를 확인한다.

검증 서버를 같은 데이터로 재시작하려면 출력된 검증 데이터 경로만 `STUDY_CAFE_UI_DATA_DIR`로 지정한다. 운영 데이터 경로를 지정하지 않는다. 최초 시드 이후 목표를 모두 삭제해도 해당 검증 디렉터리를 재사용하면 다시 생성하지 않는다.

## 문항 정정 흐름

결과·오답의 보기는 해설 작성 당시의 원문 순서로 표시한다. 시험 중에 보기 순서를 섞었다면 안내를 보여주며, 원래 해설의 A/B/C 표시와 일치시킨다. 내 답안은 보기 ID로 저장하고 내용으로 표시하므로 순서 변경이 점수나 답안을 바꾸지 않는다. 정정된 해설에는 해당 정정 버전의 순서를 사용한다.

실제 Codex 브라우저 검증은 `node --import tsx scripts/live-ui.ts`로 격리 DB·4320 서버를 실행한다. 연결 토큰은 출력에서 확인한다. Codex가 PATH에 없으면 현재 설치 경로를 `CODEX_BIN`으로 지정하며, 앱 업데이트 뒤 이전 버전의 실행 경로를 재사용하지 않는다. `STUDY_CAFE_LIVE_DATA_DIR`에 출력된 검증 DB 경로를 지정하면 이어서 실행한다. 실제 관리 로그인 한도를 사용하며 유료 API 대체 연결은 없다.

문제은행 → 문제 상세 → 문제 수정 → 새 버전 저장 → 검토 상태 직접 변경 → 필요할 때 과거 응시 재채점 순서다. 수정 시 출처·원문 근거·계열·지문 묶음은 유지한다. 문항 유형과 원출처를 바꾸는 편집은 지원하지 않는다. 검토 전에는 새 시험에 사용되지 않는다.

이전 버전은 읽기 전용이다. 동시 수정 시 입력 내용을 유지하고 최신 버전을 불러와 비교할 수 있다. 최신 내용으로 교체하거나 내 수정 내용을 유지한 뒤 사용자가 다시 저장한다.

재채점은 최신의 사용 가능한 버전에만 허용한다. 본문·보기·배점이 같은 객관식은 정정 정답으로 계산하고, 변경된 문항이나 주관식은 수동 검토로 넘긴다. 과거 시험 원문은 보존한다. 같은 정정을 재실행해도 이미 적용한 결과와 이후 수동 채점을 덮어쓰지 않는다.

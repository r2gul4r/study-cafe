# 토큰 입력 없는 로컬 연결

2026-10-16 구현. 앱 접속 보호를 유지하면서 사용자가 토큰 파일을 열어 복사하는 절차를 없앴다. Codex 로그인과 별개인 공부방 접속 인증이며 새 API 키·외부 인증 서비스·추가 의존성은 사용하지 않는다.

## 사용 방법

- 처음 실행: `.\scripts\start.ps1` 또는 빌드 후 `pnpm start`. 기본 브라우저가 열리고 공부방에 연결된다.
- 서버가 켜져 있을 때 다시 열기: `.\scripts\start.ps1 -Open` 또는 `pnpm open`.
- 같은 브라우저에서 주소만 다시 열면 30일 동안 자동 연결된다. 연결 해제·쿠키 삭제·만료·다른 포트/브라우저에서는 실행기로 다시 연결한다. 서버가 꺼져 있으면 먼저 실행한다.
- 사용자 지정 데이터 폴더는 서버와 실행기에 동일한 `STUDY_CAFE_DATA_DIR`를 지정한다. `server-address.json`의 마지막 실행 주소를 사용한다.
- 개발 화면: 백엔드와 Vite를 실행한 뒤 `pnpm open http://127.0.0.1:5173`. 허용 Origin에 있는 로컬 주소만 지원한다.
- 자동 브라우저 열기 끄기: `STUDY_CAFE_NO_OPEN=1` 또는 Windows 실행기의 `-NoBrowser`.

`ui-fixture.ts`/`live-ui.ts`는 고정 테스트 인증을 사용하는 격리 검증 서버다. 시작할 때 브라우저를 자동 연결한다. 다시 연결하려면 출력된 데이터 폴더를 해당 스크립트의 환경 변수로 지정하고 검증 서버를 재시작한다. 일반 실행기의 `pnpm open`은 `main.ts`로 실행한 공부방을 대상으로 한다.

## 연결 과정과 보호

1. 서버는 계속 `127.0.0.1`에만 바인딩한다. 기존 `session-token`은 로컬 실행기·CLI에만 필요하며 학습 데이터 API의 인증을 없애지 않는다.
2. 시작 시 또는 Bearer 인증을 통과한 `/api/browser/launch` 요청에만 256비트 일회용 코드를 발급한다. 5분 후 만료하고 한 번 사용하면 폐기한다. 서버 재시작 후에도 재사용할 수 없다.
3. 실행기는 `/#/connect?code=...` 형태의 로컬 주소를 연다. 장기 토큰은 URL·로그에 넣지 않으며, 프래그먼트는 HTTP 요청에 전송되지 않는다. 프론트는 교환 요청 전에 `history.replaceState`로 프래그먼트의 코드를 제거한다. 이미 열린 탭에 링크가 전달돼도 처리하고 StrictMode 중복 교환을 막는다.
4. `/api/browser/connect`에서 일회용 코드를 검증하고 별도의 브라우저 세션을 발급한다. 쿠키는 `HttpOnly`, `SameSite=Strict`, `Path=/api`, 30일 만료다. 평문 로컬 HTTP만 사용하므로 `Secure` 쿠키는 사용하지 않는다. 브라우저 인증값을 JS 저장소에 보관하지 않는다.
5. 쿠키 이름과 서버 세션을 Host·포트에 묶는다. 브라우저 요청에는 `X-Study-Cafe-Client: browser`가 필요하고, Origin은 허용 목록과 현재 Host를 모두 만족해야 한다. Fetch-Site가 있으면 same-origin/none만 허용한다. 다른 사이트의 폼·교차 출처 요청·직접 자료 링크만으로 API를 호출할 수 없다. 이미지·PDF 다운로드도 같은 헤더를 보내는 fetch를 사용한다.
6. 기존 sessionStorage 토큰이 있는 탭은 Bearer로 한 번 교환한 뒤 토큰을 지우고 쿠키 연결을 확인한다. ‘연결 해제’는 서버의 세션을 취소하고 쿠키도 지운다. 복사해 둔 쿠키도 다시 사용할 수 없다.

`browser-sessions.json`에는 인증값의 SHA-256 해시·Host·만료 시각만 저장한다. 세션은 최대 32개, 미사용 실행 코드는 최대 16개로 제한한다. 장기 토큰이 바뀌면 저장된 브라우저 연결을 무효화한다. 인증 파일 손상 시 새 로컬 연결을 요구한다. 인증·실행 주소 파일은 Git과 학습 백업에 포함하지 않는다. 다른 PC로 공부 기록을 복원한 뒤 그 PC의 실행기로 새로 연결한다.

쿠키 자체는 브라우저 규격상 포트별로 전송되지 않는다. 서버가 세션을 Host·포트에 묶고 출처/헤더를 검증해 다른 포트에서의 사용을 거부한다. 이 기능은 외부 웹페이지의 무단 요청을 막기 위한 것으로, 같은 OS 계정으로 파일을 읽거나 로컬 프로그램을 제어할 수 있는 공격자까지 격리하는 구조는 아니다.

## 검증

- 자동 회귀 6개 추가, 전체 135개 통과. 무인증 거부, 일회용/재사용/만료, Host·Origin·Fetch-Site·헤더 경계, 다른 포트, 기존 Bearer 전환, 로그아웃 후 복사 쿠키 무효화, 재시작 보존, 장기 토큰 변경, 손상 인증 파일, 백업에서 인증 제외, 개발 프록시 주소 제한을 검사한다.
- 서버·프론트 타입 검사와 빌드 통과. 기존 학습 기록과 AI 작업 흐름은 변경하지 않는다.
- 실제 브라우저 검증 및 남은 범위는 [검증 기록](VERIFICATION.md)의 2026-10-16 항목을 따른다. macOS/Linux 실행기와 다른 컴퓨터의 새 설치는 아직 미검증이다.

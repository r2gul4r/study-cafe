작성 기준: **2026-10-15** · 코드 기준: `laptop` / `d9c8a2e`

## 전체 완성까지의 순서

### 1. 자료 처리 개선을 한 차례 마무리

준비한 이미지 선택 전달·추가 요청을 구현하고 검증한다. 자동 영역 추천은 수동 선택의 불편을 줄이는 후속 기능으로 둔다. 모든 PDF 형식을 해결할 때까지 자료 처리만 계속 개발하지 않는다.

변경 지점·추가 요청 계약·재개와 회귀 조건은 [PDF 이미지 전달 설계](PDF_IMAGE_DELIVERY_PLAN.md)를 따른다. 작성 시점에는 설계만 있고 선택 전달 기능은 아직 적용하지 않았다.

### 2. 새 목표로 전체 학습 흐름 검증

기존 검증 자료를 재사용하는 수준을 넘어, 서로 다른 분야의 새 목표에서 **목표 입력 → 조사 → 25문항 → 풀이 → 채점 → 오답 → 변형 복습**을 실제 Codex로 연결해 확인한다. 특정 과목용 코드를 추가하지 않고 발견되는 공통 문제를 고친다.

### 3. 매일 쓰는 사용 흐름 다듬기

자료 부족·검토 보류·계정 제한이 생겼을 때 이유와 다음 행동을 분명히 보여주고, 오늘 복습과 다음 시험으로 자연스럽게 이어지게 한다. 여러 날의 기록이 쌓였을 때도 복습과 진도가 제대로 갱신되는지 확인한다.

### 4. 설치·이동·복구 검증 후 첫 버전 확정

다른 PC에서 설치하고 Codex를 연결한 뒤 백업을 복원해, 문항·첨부·응시 기록을 다시 열어본다. 현재는 **같은 PC의 다른 폴더로 복원하는 것까지** 검증했다. [백업 복원 안내](BACKUP_RESTORE.md)를 참고한다.

집의 `develop` 변경과 노트북의 `laptop` 통합도 확인한다. 집 컴퓨터의 미푸시 변경을 원격에 있다고 추정하거나 덮어쓰지 않는다.

### 5. 지원 범위를 넓히는 확장

스캔 PDF OCR, 청해 플레이어, 코드 실행 채점, 시험별 섹션 엔진은 아직 없다. 첫 버전 이후 확장할 수 있지만, **청해를 포함한 시험 전체를 지원한다고 하려면 청해 기능까지 필요하다.**

## 첫 완성 기준

**지원하는 웹·텍스트 PDF 자료로 새 목표를 만들었을 때, 개발자가 코드를 수정하지 않아도 한 회차 학습과 이후 복습을 끝낼 수 있고, 실패하면 앱에서 원인을 확인하고 이어갈 수 있는 상태**를 첫 완성 기준으로 삼는다.

따라서 다음 PDF 개선을 끝낸 뒤에는 **새 목표로 전체 흐름 검증 → 실제 사용성 정리 → 다른 PC 설치·복원 검증**으로 넘어간다. 모든 자료 형식과 시험의 완벽한 지원을 첫 버전의 완료 조건으로 삼지 않으며, 미지원 기능과 검토가 필요한 결과는 사용자에게 분명히 표시한다.

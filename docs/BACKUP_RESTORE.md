# 백업 확인과 다른 컴퓨터에서 복원

설정 → 학습 기록 백업 → **복원 전 내용 확인**을 누르면 선택한 백업의 DB·첨부 해시와 DB 무결성을 다시 검사한다. 통과한 백업의 생성 시각, 확인 시각, 목표·자료·문항/버전·시험·응시·첨부 수와 로컬 폴더를 표시한다. 현재 공부방의 수치와 섞지 않는다.

다른 컴퓨터에는 백업 폴더 전체(`study-cafe.db`, `assets`, `manifest.json`)를 복사한다. 화면의 백업 경로를 새 컴퓨터의 위치로 바꾸고 복원할 데이터 폴더를 입력한다. 기존 공부방과 다른 새 폴더를 권장한다. 화면은 대상 경로의 존재 여부를 검사하거나 파일을 바꾸지 않는다.

서버 종료·백업으로 교체 조건을 확인하면 PowerShell용 명령을 표시한다. 프로젝트 의존성을 설치하고 빌드한 환경에서, 서버를 종료한 뒤 프로젝트 폴더의 터미널에 실행한다. 경로의 공백·작은따옴표·명령 치환 문자는 리터럴 문자열로 처리하고 복원 명령이 실패하면 서버 시작을 중단한다.

실제 복원은 기존 `pnpm restore <백업폴더> <데이터폴더>` CLI가 수행한다. 실행 중인 대상 폴더는 잠금으로 거부하고, 기존 DB가 있으면 교체 전 백업을 만든다. 두 컴퓨터의 기록을 병합하는 기능이 아니다. 앱 세션 토큰과 Codex 로그인 정보는 백업에 포함되지 않으므로 새 컴퓨터에서 다시 연결한다.

읽기 전용 `GET /api/backups/:id/restore-plan`은 인증이 필요하다. 허용된 백업 ID만 읽고, 백업 폴더와 manifest ID가 일치해야 한다. 손상된 백업은 수치/명령 준비 화면을 열지 않는다. 복원 실행 시점에 CLI가 무결성을 다시 확인한다.

검사에서는 백업 후 새로운 목표를 추가한 뒤 백업의 이전 수치가 표시되고 현재 기록이 유지되는지, 인증·잘못된 ID·첨부 손상 거부와 명령 인용을 확인했다. 브라우저에서 분리된 검증 공부방의 백업 생성·내용 확인·경로 입력·명령 표시를 확인했으며 실제 사용자 공부방을 복원하지 않았다.

2026-10-15에는 공개 PDF 검증 자료의 백업을 같은 PC의 새 임시 폴더에 실제 CLI로 복원했다. 목표 1개·자료 2개·문항 23개·문항 버전 27개·첨부 19개가 보존됐다. 서버 시작 전 DB 해시 일치, 원본/정답/잘라낸 이미지의 인증 API 응답과 파일 해시, 표시 영역 캐시, 검토 대기 상태, 새 세션 토큰 생성을 확인했다. 이전 승인 버전과 잘라낸 버전의 보존도 자동 회귀 검사에 포함했다. [검증 근거](evidence/region-restore-2026-10-15.json).

이는 같은 컴퓨터의 새 폴더로 옮긴 검사이며 다른 컴퓨터의 OS·Node 설치·Codex 로그인까지 검증한 결과는 아니다. 다음 컴퓨터에서는 저장소의 `laptop`을 받은 뒤 Node 24 이상과 의존성 설치·빌드를 확인하고, 백업 폴더를 복사해 새 데이터 폴더로 복원한다. 원본과 영역 이미지, 목표 수, 기존 응시 점수를 확인한 다음 그 폴더를 계속 사용한다.

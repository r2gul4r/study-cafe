# 실제 Codex 주관식 채점 검증 · 2026-10-14

기존 ChatGPT 관리 로그인의 Codex App Server로 **11개 답안 사례**를 확인했다. 별도 임시 DB에서 실제 `grade_attempt` 워크플로우를 실행했으며, 기대 점수는 모델에 전달하지 않았다. 유료 API 대체 연결·추가 결제·웹 검색은 사용하지 않았다. 모델 이름은 따로 지정하거나 기록하지 않았으며 기존 설정과 `medium` 추론 강도를 사용했다.

## 확인한 결과

완료한 채점은 정답 7건, 의도한 감점 3건, 부적합 기준에 따른 보류 1건이다. 이 소규모 사례에서 의미가 같은 답이나 요구하지 않은 설명 누락을 이유로 감점을 확정한 사례는 관찰하지 못했다. 모든 목표·언어·답안의 정확도나 모델의 반복 일관성을 보장하는 결과는 아니다.

실제 판단 예:

- 추가 설명 기준: “문항은 출력 결과만 줄바꿈하여 쓰도록 요구합니다.” 원리 설명 부분은 추가 조건으로 판단해 점수와 오답 기록에 반영하지 않았다.
- 명시한 설명 누락: “출력 결과는 정확하지만, 명시적으로 요구한 3이 출력되지 않는 이유가 빠졌습니다.” 두 독립 평가가 1/2점으로 일치했다.
- 과거 답안: 출력의 반복 값과 들여쓰기 설명을 함께 읽어 이미 충족한 정보로 인정했다. 기존 공부방의 확정 3/4점·시험 34/39점은 자동 정정하지 않았다.

### 기대 결과를 바로잡은 사례

초기 검증 스크립트는 `historical-overstrict`가 반드시 보류되어야 한다고 예상했다. 실제 모델은 답안 전체에 `1,3,5`가 이미 있으므로 4/4점을 줬고, 이는 사용자의 요구에 맞는 결과다. 따라서 이 사례는 **만점 또는 기준 불명확에 따른 보류**를 허용하되 감점은 실패로 처리하도록 검증 기준을 수정했다. 명백히 요구하지 않은 원리 설명을 강제하는 `unrequested-explanation` 사례는 여전히 보류만 허용한다. 실제 점수나 모델 응답을 수정하지 않았으며 최초 실패 표시도 근거 파일에 남겼다.

## 호출 제한과 수정

한 번에 11건이 모두 성공한 검사가 아니다. 5차례 실행에서 총 **43회 호출, 성공 29회·실패 14회**가 있었고, 성공·실패 호출의 대기 시간 합은 약 **383초**였다. 처음 10회 실패는 상세 원인을 수집하지 않아 원인을 확정할 수 없다. 이후 4회 실패에서는 HTTP 429 요청 제한을 확인했다. 연결 재시도 후 성공한 70초짜리 호출도 있었다. 한도 초기화 시각이나 정확한 토큰 소비량은 측정하지 않았다.

| ----------- | ----------- | ------------------------------------------------------------------- |

마지막 문항 검토 실패 시 상태가 기존 `usable`로 남아도 성공으로 세지 않았다. 과거 문항 검토의 성공 근거는 앞선 `ys0MMG` 실행이며, 마지막 실패로 대체하지 않는다. [보존한 실제 결과](evidence/live-grading-2026-10-14.json)에 실행별 성공 여부와 판단 근거를 기록했다. 자격 증명·사용자 DB·임시 파일의 기기별 절대 경로는 포함하지 않았다.

수정 사항:

1. `turn/completed`의 최종 오류에서 알려진 제공자 코드와 HTTP 상태만 보존한다. 429는 `CODEX_RATE_LIMITED`, 계정 한도는 `CODEX_USAGE_LIMIT`로 안내한다. 원본 오류 메시지·추가 상세의 개인 정보는 저장하지 않는다. 중간 연결 오류 후 성공한 응답은 실패로 바꾸지 않는다. 형식은 [공식 App Server 오류 문서](https://learn.chatgpt.com/docs/app-server)를 확인했다.
2. 요구사항 검토·첫 채점·감점 재검토를 각각 저장한다. 재검토 중 실패한 작업을 **재개**하면 완료한 단계를 다시 호출하지 않는다. 새 작업 생성은 별도 실행이다. 인용·기준 ID 등이 잘못된 응답은 저장하지 않아 재개 시 교체할 수 있다.
3. 실제 검증 스크립트는 최종 Codex 실패에서 나머지 호출을 중단한다. 자동 재실행·유료 대체 경로는 없다. 실패를 0점이나 오답으로 저장하지 않는다.

새 자동 검사 6개로 오류 구분·민감한 오류 상세 제외·일시 오류 회복·감점 재검토 중 한도 실패 후 재개·잘못된 인용 재생성을 확인했다. **전체 74/74, 백엔드·프론트 타입 검사, 프로덕션 빌드 통과.** 채점 지시와 과목별 제품 분기는 이번에 추가하지 않았다.

## 다른 컴퓨터에서 재현

설치와 기존 Codex 로그인을 마친 뒤 저장소 루트에서 실행한다. `--live`를 붙인 검사만 실제 계정 사용량을 소모하며 일반 `pnpm check`에는 포함되지 않는다.

```powershell
# 호출 없이 사례 목록만 확인
pnpm exec tsx scripts/live-grading.ts

# 작은 묶음으로 실제 실행
pnpm exec tsx scripts/live-grading.ts --live --only=meaning-paraphrase,output-only

# 필요할 때 전체 실행; 한도 실패 시 중단
pnpm exec tsx scripts/live-grading.ts --live
```

실행 파일을 찾지 못하면 `$env:CODEX_BIN = (Get-Command codex).Source`로 경로를 지정한다. `chatgpt` 로그인 유형이 아니면 실제 검사는 중단한다. 각 실행은 새 임시 DB와 `report.json`을 만들고 위치를 출력한다. 실패 기록을 보존한 채 회복 후 미완료 사례만 `--only`로 지정한다. 자동 채점의 재개 동작은 앱의 기존 작업 재개 기능을 사용한다.

시험 스냅샷 불변, 정답/오답별 복습 이벤트, 보류 시 오답 제외도 검사한다. 사례의 천문·사진·단위·코드는 범용 동작 확인용이며 제품 로직의 과목 조건이 아니다.

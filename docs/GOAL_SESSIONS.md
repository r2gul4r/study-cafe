# 목표별 AI 세션과 DB

목표를 저장한 뒤 첫 AI 작업에서 전담 Codex 대화를 만든다. 같은 목표의 후속 작업은 그 대화를 재개하며, 앱 종료 후에도 SQLite에 저장한 연결을 사용한다. 기존 Codex 로그인·계정 한도를 사용하며 별도 API 키를 추가하지 않는다.

## 역할과 저장 위치

**내 목표 → 목표 펼치기 → 이 목표의 AI 세션**에서 목표별 모델·추론을 선택하면 즉시 자동 저장한다. DB v4의 `goal_agent_settings`에 저장하며, 앱 재시작·백업 복원에도 유지한다. 매 호출 시작에 설정을 읽고 전담 대화 ID는 그대로 재개한다. 검증·재채점의 대화 분리는 유지하며 이 목표가 선택한 모델·추론만 공유한다. 실행 중인 호출을 중단하거나 완료된 작업을 재실행하지 않는다. [구현·실제 검증](SESSION_SETTINGS_2026_10_18.md).

브라우저는 공부방 백엔드 API에 요청하고, 백엔드는 로컬 `codex app-server` 프로세스와 JSON-RPC로 통신한다. Codex 앱에 열린 사용자 채팅을 클릭하거나 조작하는 방식이 아니다. 작업 목록의 개별 작업 ID와 AI 대화 ID는 별개이며 범위 설계와 문제 생성이 서로 다른 작업이어도 같은 목표의 전담 대화를 사용한다.

| 구성 | 저장·처리 내용 |
| --- | --- |
| SQLite `goal_sessions` | 목표 ID, Codex thread ID, 생성·최근 연결 시각 |
| 기존 공부방 DB | 확정 목표·범위·자료·문항·응시·채점·오답 노트·작업 체크포인트 |
| Codex 영구 스레드 | 목표에 대한 일반 AI 작업의 대화 이력. Codex가 관리하는 로컬 저장소에 보관 |
| 백엔드 | 현재 DB 상태 제공, 결과 검증·저장, 목표별 요청 직렬화 |

전담 세션: `plan_goal`, `research_sources`, `extract_existing_questions`, `generate_question`, `generate_variant`, `summarize_misconceptions`.

독립 임시 세션: `verify_question`, `audit_rubric`, `grade_answer`, `review_short_answer`. 출제·앞선 점수 이력이 독립 평가에 섞이지 않도록 첫 채점도 분리한다. 새로 추가한 미분류 역할은 기본적으로 임시 세션이다. 임시 세션에는 전담 대화 이력이나 목표 전체 DB 요약을 넣지 않고, 기존 작업이 지정한 문제·근거·답안만 전달한다.

## 호출·재시작

범위 설계(`plan_goal`)와 자료 조사(`research_sources`)의 AI 실행에는 고정 시간 제한을 두지 않는다. 자료를 계속 찾는 정상 작업이 기존 3분 제한으로 중단되는 것을 방지한다. 에이전트 작업 화면의 일시정지·취소, 프로세스 종료·연결 오류 처리는 유지한다. 그 외 AI 역할은 기본 3분 제한을 유지하며, 통신 요청과 개별 자료 다운로드의 제한 시간은 별개다. 이미 시간 초과로 실패한 작업은 업데이트 후 재개해야 한다.

1. 작업의 goal/source/question/exam/attempt 연결로 목표를 확인한다. 서로 다른 목표 참조는 거부한다.
2. 첫 요청은 `thread/start(ephemeral=false)`. 응답 ID를 **추론 시작 전에** DB에 저장한다.
3. 이후 요청은 `thread/resume` 후 같은 thread에 `turn/start`. 검색 허용 여부와 도구 제한을 매번 적용한다.
4. 현재 역할·입력·DB 요약을 매번 전달한다. 최신 목표/범위, 자료 상태 최대 30개, 노트 최대 5개(각 6,000자 발췌), 최근 응시 10개, 최신 평가 상태 집계를 포함한다. 원문·문제·답안·고정 시험 범위는 해당 작업 입력에서 제공한다.
5. 현재 작업의 고정 버전과 최신 DB 기록을 우선한다. 과거 AI 출력은 저장·승인된 사실로 간주하지 않는다. AI는 DB를 직접 수정하지 않는다.

동일 목표의 요청은 직렬화한다. 취소·시간 초과 시 turn 중단 완료를 기다린다. 중단 응답이 멈추면 5초 뒤 프로세스를 종료해 이전 작업과 다음 작업의 중첩을 막는다. 복구 불가능한 프로세스 장애 때 다른 진행 중 요청도 실패할 수 있으며 작업 기록에서 재개한다.

작업 체크포인트와 AI 대화 이력은 별개다. 완료된 `job_steps`는 재실행하지 않는다. 저장 직전 장애가 발생한 미완료 단계는 다시 호출될 수 있으며, 이전 대화에 응답이 있어도 DB에 반영됐다고 추정하지 않는다.

## 복구·백업·삭제

- 대화가 없다는 명시적인 Codex 응답일 때만 새 전담 대화를 만들고 현재 DB 요약을 제공한다. 작업 이벤트에 `goal_session`과 `created`/`resumed`/`recovered`를 기록한다.
- 로그인·통신·공급자 오류는 기존 연결을 유지한 채 실패로 남긴다. 이미 실행 중인 대화에는 새 turn을 겹쳐 실행하지 않는다.
- DB v1은 데이터 폴더를 열 때 v2로 자동 이전한다. v1 백업 복원도 지원한다. v2 DB는 이전 버전 앱으로 열 수 없으므로 이전 실행 파일을 사용할 때는 v1 백업이 필요하다.
- 백업에는 목표별 연결과 학습 기록이 포함된다. Codex의 별도 대화 저장소와 로그인 정보는 포함하지 않는다. 다른 PC에서 대화를 찾지 못하면 DB 기반으로 새로 구성하며 이전 대화 원문 전체를 복구하지는 않는다.
- 목표 삭제 시 DB 연결도 함께 삭제한다. Codex 저장소의 대화 원문이나 기존 백업은 자동 삭제하지 않는다.
- 긴 대화는 Codex의 컨텍스트 관리 영향을 받는다. 핵심 학습 상태는 DB에 유지하며 전체 대화를 무제한으로 기억한다고 가정하지 않는다.

## 검증

- `node --import tsx --test tests/agent.test.ts tests/goal-sessions.test.ts`: 디스크 이력을 가진 별도 JSON-RPC 프로세스로 재시작·격리·복구·취소·DB 이전·체크포인트를 검증한다. 외부 추론 없음.
- `node --import tsx scripts/goal-session-probe.ts --live`: 임시 공부방 DB에서 실제 Codex 3회 호출. 임의 표식 기억 → 프로세스/DB 재시작 후 같은 대화에서 회수 → 독립 재검토에는 표식이 없는지 확인한다. 기존 사용자 공부방은 수정하지 않는다. 실행 중인 Codex 버전·계정 한도에 영향을 받는다.
- `pnpm check`, `pnpm build`: 전체 회귀·서버/웹 타입·빌드 확인.

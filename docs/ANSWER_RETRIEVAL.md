# 긴 정답표 검색 · 2026-10-15

## 바뀐 처리

기존에는 정답 자료의 앞·뒤 구간, 질문과 단어가 겹치는 구간, 앞에서부터의 보충 구간을 합친 뒤 10개로 잘랐다. 한 자리 문항 번호는 단어 검색에서 빠졌으며 여러 자료의 표지만으로 자리가 소진될 수 있었다. 합친 결과에는 전체 문자 수 제한도 적용되지 않았다.

`src/answer-retrieval.ts`는 현재 목표에 연결된 이용 가능한 정답 자료의 최신 구간 전체로 작업별 검색 색인을 만든다. 문항 번호를 완전한 번호로 비교하고, 드문 단어와 주변 문맥을 함께 고려한다. `3`과 `30`은 다른 번호다. 전각 표기, 번호 구분자, 숫자·문자 정답 행을 후보 검색에 사용한다. 목표 이름, 과목, 시험명, 자료 URL에 따른 제품 분기는 없다.

1. 내용이 맞는 구간부터 선택한다. 해당 자료의 앞·뒤 판본 정보와 같은 판본의 앞 1개·뒤 2개 구간을 예산 안에서 추가한다. 이어지는 구간이 빠지면 그 다음 구간을 연속 근거라고 취급하지 않는다.
2. 한 요청의 정답 근거는 최대 **10개 구간·56,000자**다. 인용용 원문을 자르지 않는다. 별도로 최대 48개의 짧은 탐색 항목을 전달하며, 이 미리보기는 인용 근거가 아니다.
3. Codex가 정답·판본·뒤쪽 해설을 찾지 못하면 `answerSearch`로 검색어나 최대 3개의 구간 ID를 요청한다. 미리보기 밖의 구간도 전체 색인에서 검색한다. 새 검색 대상과 이전 핵심 근거를 최대 3개의 중심 구간으로 유지해서 판본을 찾는 동안 정답이 사라지지 않게 한다. 질문 구간당 추가 검색은 최대 **2회**다. 연결하지 않은 구간 ID, 같은 결과의 반복, 검색 한도 소진은 미해결로 남긴다.
4. 검색 요청 응답은 문항 저장과 분리한다. 새로 전달받은 전체 원문에서 추출한 뒤 기존의 정확한 인용·문항 번호·양쪽 판본·연속 구간 검사를 거친다. 독립 Codex 검토를 통과해야 출제할 수 있다. 후보 순위나 번호 일치만으로 사용 가능 처리하지 않는다.
5. 검색 응답과 추출 결과를 체크포인트에 보관한다. 재개 중 범위/문제/정답 판본이 바뀌면 서로 다른 판본을 섞지 않고 새 추출을 요청한다. 이미 저장한 문항은 유지한다. 작업 이벤트의 `answer_retrieval`에 전체/선택 구간 수, 문자 수, 선택 이유, 추가 검색 횟수를 남긴다.

새 자료를 등록·수집하고 정답표를 연결하면 같은 경로를 재사용한다. 자료별 코드 수정이나 유료 임베딩 서비스가 필요하지 않다. 과거 문항과 학습 기록을 자동 재작성하지는 않으며, 개선은 새 추출 작업부터 적용한다.

## 검증 방법

- 자동 검사는 뒤쪽의 숫자 전용 정답표, 비슷한 번호, 반복되는 번호의 본문 구분, 여러 자료 표지의 자리 선점, 원문 단위 예산, 명시적 추가 검색, 검색·추출 체크포인트 재개, 무한 재검색 방지, 다른 자료 접근과 판본 변경 거부를 포함한다.
- `scripts/live-answer-retrieval.ts`는 기본 실행 시 외부 호출하지 않는다. `--live`를 명시해야 기존 ChatGPT 로그인의 Codex를 사용하며 유료 API로 대체하지 않는다. 호출 수를 제한하고 계정/연결 오류 뒤 자동 반복하지 않는다. 실제 호출은 계정 사용량을 소비한다.
- 직접 작성한 광학·영문법·대수 자료와 별도 정답표를 새 목표에 넣는다. 72~96개 구간의 뒤쪽 정답, 같은 번호의 다른 절, 다음 구간의 최종 답을 확인한다. 공백으로 8,000자 경계를 고정한 합성 자료이므로 실제 PDF 페이지 수로 표현하지 않는다.
- 추가 공개 PDF는 [MIT OCW 6.042J Fall 2010 시험 목록](https://ocw.mit.edu/courses/6-042j-mathematics-for-computer-science-fall-2010/pages/exams/)에 있는 **2008 final exam**의 문제 9다. Tom Leighton·Marten van Dijk, [CC BY-NC-SA 4.0 및 이용 조건](https://ocw.mit.edu/pages/privacy-and-terms-of-use/). 문제 20쪽 중 17쪽, 정답 16쪽 중 13쪽의 연결을 검사하고 두 원본 이미지를 직접 대조한다. 기존 검색도 이 PDF의 해당 구간은 찾았으므로 이 사례를 검색 실패 개선의 단독 증거로 제시하지 않는다.

재현:

```powershell
$env:CODEX_BIN = (Get-Command codex).Source
node --import tsx scripts/live-answer-retrieval.ts --live --max-calls=14
# 실패한 단계만 다시 확인: 보고서 marker가 있는 임시 폴더만 허용
node --import tsx scripts/live-answer-retrieval.ts --live --cases=pdf --resume=<임시폴더> --max-calls=4
# 이미 끝난 검증 사례를 수정 후 새 작업으로 재검증: 기존 결과는 previousRuns에 보존
node --import tsx scripts/live-answer-retrieval.ts --live --cases=edition --resume=<임시폴더> --new-extraction --max-calls=6
```

저장소에는 원본 시험/정답, 임시 DB, 인증 정보 대신 검증 요약을 남긴다. 원본 URL·호출별 입력 구간·결과·실패 이력은 근거 JSON을 참고한다.

## 실제 확인된 개선과 실패 이력

최종 **120개 테스트·타입 검사·빌드 통과**. 실제 Codex 16회 시도 중 정상 응답 15회, 시간 초과 1회이며 호출 시간 합은 448.973초다. 합성 자료 5개와 실제 공개 PDF 1개의 최종 검색·연결을 확인했다. 사용 가능은 합성 문항 5개, 공개 PDF 문항 1개는 원본 검토 대기다. [호출·비교 결과 JSON](evidence/live-answer-retrieval-2026-10-15.json)을 함께 보관한다.

- 80구간 정답표의 67번째 구간에 `3 | B`만 있는 사례에서 기존 선택기는 정답을 누락했다. 새 선택기는 해당 구간과 앞뒤 문맥·판본을 함께 찾아 실제 추출·독립 검토를 통과했다. 이 결과는 단순히 잘 되던 자료를 새 방식으로 다시 실행한 사례와 구분한다.
- 판본 정보가 45번째 구간, 정답이 67번째 구간에 있는 사례에서 실제 Codex가 판본 추가 검색을 요청했다. 초기 구현은 판본을 찾는 동안 정답 구간을 버려 2회 응답 뒤 미해결이 됐다. 핵심 근거 유지로 수정한 뒤 같은 자료의 새 작업에서 **검색 요청 → 근거를 합친 추출 → 독립 검토** 3회로 사용 가능해졌다. 기존 미해결 결과는 삭제하지 않았다.
- 검증 스크립트의 PDF 권한 값 `licensed`가 실제 계약(`allowed`)과 달라 준비 단계에서 거부된 실행도 보존했다. 제품의 자료 검사를 완화하지 않고 스크립트 값을 수정했다. 해당 실패 자체에서는 PDF Codex 호출이 발생하지 않았다.
- 공개 PDF의 최초 요청은 240초 제한으로 중단됐다. 같은 단계에서 수동 재개 후 추출 37초·독립 검토 32초로 완료했다. 자동 무제한 재시도나 유료 API 대체 경로는 추가하지 않았다.
- 공개 PDF의 인용·문항/정답 연결·이미지 충실성·학습자 정답 이미지 비노출은 확인됐다. 독립 검토는 빈 그래프를 제외하는 전제와 경로 길이 정의를 제공 자료에서 확인하지 못했고, 모범답안의 타당성을 보류했다. 이는 모델이 기록한 검토 쟁점이며 원문 오류를 확정한 선언은 아니다. 검증기의 모든 원문을 `usable`로 기대하던 가정을 고쳐 검색 성공과 원문 검토 상태를 분리했다. 보류 기준이나 문항을 수정하지 않았으며 이 마지막 감사에는 추가 AI 호출이 없었다.

## 남은 한계

단어·번호 기반 검색이며 모든 언어·표 구조를 의미적으로 이해하는 검색은 아니다. 텍스트층이 없는 스캔 PDF의 OCR, 표 구조 복원, 번호/판본이 전혀 없는 자료, 예산을 넘는 해설은 여전히 별도 처리가 필요하다. 두 번의 추가 검색 후에도 불확실하면 미해결로 남긴다. 사진 한 장에 문제와 정답이 섞여 있을 때 응시자용 문제 영역 잘라내기는 별도 작업이다. 작은 실제 검증 묶음을 통과했다고 모든 목표나 모든 정답표의 정확도를 보장하지 않는다.

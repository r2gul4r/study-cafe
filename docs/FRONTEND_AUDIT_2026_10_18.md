# 프론트엔드 화면·버튼 검증 · 2026-10-18

기존 React 프론트와 API 연결을 유지하면서 화면 깨짐을 재현하고 수정했다. 전체 교체나 외부 디자인 생성 서비스는 사용하지 않았다. `home`의 기존 미커밋 모델·추론 설정/실행기 작업 위에 적용했으며, 이 작업에서는 커밋·병합·푸시하지 않았다.

## 수정한 문제

1. **설정 패널 중복 렌더링:** 같은 부모 아래 `SessionSettings`와 화면 컴포넌트가 같은 `goal.id` 키를 사용했다. 화면 이동·재조회 후 설정 패널이 12개까지 늘어나는 실제 DOM과 화면을 확인했다. 각 컴포넌트의 키를 분리하고 설정/작업 툴바를 구성했다. 최종 36개 화면 조합에서 설정 패널은 모두 1개다.
2. **자료·목표 부분 수정 시 다른 정보 초기화:** 이용 근거만 수정했는데 자료 분류가 `user_material`에서 `reference`로 바뀌었다. Zod 4의 optional 필드 내부 기본값이 PATCH 요청에도 적용됐다. 생성용 기본값을 제거한 별도 PATCH 스키마로 바꾸고, 생략 필드 보존·명시적 빈 값/null·잘못된 값의 무변경 거부를 회귀 테스트 2개로 확인했다. 실제 화면에서도 자료 분류 보존을 다시 확인했다.
3. **목표 관리 대화상자 여백 누락:** 관리·보관·삭제 미리보기에 공통 본문 여백을 적용했다.
4. **좁은 화면:** 긴 목표/자료명, 긴 코드와 경로, 폼 열, 페이지 제목/버튼, 설정 값 줄바꿈을 정리했다. 표와 코드는 필요한 내부 스크롤을 유지한다. 페이지 전체에 `overflow-x:hidden`을 씌워 문제를 숨기지 않았다.
5. **메뉴·대화상자:** 현재 화면의 메뉴 링크를 다시 눌러도 모바일 서랍이 닫히도록 수정했다. 모바일 메뉴/대화상자의 배경 스크롤을 잠그고 닫을 때 복원한다. 대화상자 Escape 닫기와 열었던 버튼으로 초점 복귀를 확인했다.
6. **동작과 상태 표시:** 홈 통계 카드를 실제 목표·복습·작업 화면에 연결했다. 탐색의 현재 페이지와 필터의 선택 상태를 ARIA로 표시한다. 입력창 스타일 충돌, 버튼/카드 간격·모서리·대비를 정리했다.

## 디자인 참고와 비용 경계

기존 녹색 공부방 정체성을 유지하면서 배경은 옅은 회색, 홈 안내는 짙은 녹색, 주요 행동은 연두색으로 정리했다. 과도한 지속 애니메이션은 추가하지 않았으며 기존 reduced-motion 처리를 따른다.

이번 프론트 작업 중 **실제 AI 추론 호출 0회, 유료 디자인 기능/크레딧 사용 0회**다. 결제·가입·API 키·새 외부 런타임 의존성을 추가하지 않았다. 이전 모델 설정 작업의 실제 Codex 호출 기록과 구분한다.

## 검증 환경

- Chrome 실제 UI, `http://127.0.0.1:4319`, `scripts/ui-fixture.ts`.
- 데이터는 `output/frontend-audit/browser-data`에 격리했다. 실제 앱과 같은 Fastify API, SQLite, 자료 처리, 시험·채점·복습 로직을 사용한다.
- AI 경계만 `AgentPort` fixture다. 목표 초안·요약·특정 정정 검토는 고정 응답이며, 그 밖의 추론 요청은 의도적으로 실패하거나 실행 중 취소했다. AI 정답률이나 실제 생성 품질의 증거가 아니다.
- 자료는 직접 작성한 텍스트/PDF이며 Python 예제 실행과 비공개 테스트 채점은 실제 로컬 실행기를 사용했다.
- 변경 전 프론트는 `output/frontend-audit/before-src`, 원래 중복 화면은 `output/frontend-audit/duplicate-settings-before.png`에 보관했다.
- 운영 학습 DB는 수정하지 않았다. 4317 서버는 최종 점검 시 실행 중이 아니었으며, 검증 미리보기만 4319에서 유지했다. 바탕화면 실행기는 다음 시작 시 현재 코드를 빌드한다.

## 반응형·자동 검사

홈·목표·자료·문제은행·시험과 기록·오답 노트·복습 일정·작업·설정의 **9개 화면 × 320/390/768/1280px = 36개 조합**을 최종 빌드에서 다시 측정했다. 가로 넘침 0, 중복 설정 패널 0. 표 자체의 가로 스크롤은 의도한 동작이다. 모델 설정·PDF 상세·정정 비교 대화상자는 별도로 좁은 폭에서 확인했다.

- `pnpm check`: **161 통과 / 0 실패**, 서버·웹 타입 검사 포함.
- `pnpm build`: 서버·웹 빌드 통과. 최종 모바일 메뉴 수정 후 `pnpm typecheck:web`, `pnpm build:web` 재실행 통과.
- 깊은 화면 fixture 추가 후 `pnpm typecheck` 통과.
- `pnpm openapi` 재생성.
- [화면별 측정 JSON](evidence/frontend-audit-2026-10-18.json)
- [최종 데스크톱](evidence/frontend-desktop-2026-10-18.png), [최종 모바일](evidence/frontend-mobile-2026-10-18.png)
- 명령 로그·추가 화면은 Git 제외 경로 `output/frontend-audit`에 보관한다.

검증 과정에서 샌드박스의 임시 파일 rename/소켓 제한으로 실패한 명령은 일반 로컬 실행으로 재검사했다. 새 테스트의 초기 payload 타입 오류도 수정했다. 모바일 메뉴 애니메이션 중 너무 이른 클릭/화면 캡처가 있었으므로 최종 측정은 목적지 제목이 표시된 뒤 읽은 DOM 기준이다. 이를 제품 실패나 통과 증거로 섞지 않았다.

## 남은 검증 경계

이 기록은 위 실제 클릭·저장 흐름과 폭의 검증이며 모든 데이터 조합·브라우저·키보드/보조공학 동작의 완전 검증을 뜻하지 않는다. 실제 AI 생성·심사 품질, OCR 언어별 정확도, PDF 드래그 포인터/AI 영역 추천의 전체 흐름, 파일 다운로드 결과, 동시 수정 충돌 UI, 영구 삭제 실행, 실제 복원 실행은 이번 브라우저 작업에서 검증하지 않았다. 비용 금지 때문에 실제 AI로 확대하지 않았고, 영구 삭제·복원은 미리보기/명령 생성까지만 확인했다. 청해는 기존 요청대로 추가하지 않았다.

재현:

```powershell
pnpm check
pnpm build
$env:STUDY_CAFE_UI_DATA_DIR = Join-Path $PWD 'output/frontend-audit/browser-data'
# 일시정지/재개를 점검할 때만 20000 등으로 지정. 기본 0.
$env:STUDY_CAFE_UI_AGENT_DELAY_MS = '0'
node --import tsx scripts/ui-fixture.ts
```

이 보조 서버는 테스트 모델과 고정 응답을 사용한다. 실사용 실행기로 사용하지 않는다.

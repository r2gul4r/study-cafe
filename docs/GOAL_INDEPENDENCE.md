# 목표에 종속되지 않는 학습 흐름

점검일: 2026-10-14

study-cafe는 사용자가 정한 목표를 처리하는 범용 로컬 학습 앱이다. JLPT, Python 등의 이름은 테스트 입력이며 지원 과목 목록이 아니다. 새 분야를 사용하려고 앱 코드를 수정해서는 안 된다.

## 점검 결과

| 경로           | 확인한 상태와 조치                                                                                                                                                                                                  |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 목표·범위 저장 | 제목·설명·수준·영역·개념은 사용자 데이터다. 과목별 허용 목록이나 제목 검사 분기는 없었다.                                                                                                                           |
| 자료 조사      | 모든 목표에 공식 시험 범위·기출을 우선하던 지시를 수정했다. 일반 학습은 설명·학습 자료, 역량은 실용 지침·적용 예제, 시험은 공식 범위·공개 문제를 우선한다. 제목 문자열이 아닌 사용자가 선택한 목표 유형을 사용한다. |
| 기존 문제 추출 | 원문·정답표·근거 보존 규칙은 공통이다. 목표·수준도 전달하여 맥락을 유지한다. 참고 설명에서 기존 문제를 지어내지 않는다.                                                                                             |
| 새 문제·변형   | 시험과 원문 문항의 범위 버전을 전달한다. 최신 범위 변경 후에도 이전 개념을 최신 개념으로 바꾸지 않는다. 변형에도 목표·수준을 전달한다.                                                                              |
| 채점           | 객관식 정답 ID, 주관식의 고정 채점 기준을 사용한다. 과목명별 채점 코드는 없으며 과거 답안의 기준을 최신 목표로 바꾸지 않는다.                                                                                       |
| 오답 요약      | 최신 범위에 없는 과거 개념도 해당 목표의 실제 오답 근거가 있으면 처리한다. 과거 개념 이름·영역을 전달하고 다른 목표나 근거 없는 개념은 허용하지 않는다.                                                             |
| 화면 표시      | 어학 중심 목표·수준·범위·자료 입력 예시를 범용 안내로 바꿨다. 코드 표시는 fenced code의 언어 태그를 사용하며 특정 프로그래밍 언어용 기능이 아니다.                                                                  |
| 검증 데이터    | `scripts/ui-fixture.ts`, `scripts/live-smoke.ts`, `scripts/live-followups.ts`의 과목·제목·URL은 검증 입력이다. 실제 앱 초기 데이터나 과목별 워크플로우로 불러오지 않는다. 기존 검증 DB는 보존한다.                  |

## 재현 가능한 회귀 검사

`tests/goal-independence.test.ts`에서 천문(일반 학습), 사진(실무 역량), 통계(시험 준비)를 각각 다음 순서로 검증한다. 시험 사례는 가상 검증 목표이며 실제 자격시험의 공식 범위를 주장하지 않는다.

1. 목표 초안은 사용자 저장 전까지 적용되지 않는다.
2. 목표 유형에 맞는 조사 지시를 전달한다.
3. 다른 목표의 자료가 같은 DB에 있어도 출제 근거에 섞이지 않는다.
4. 25문항 시험 생성 후 학습 범위를 바꿔도 원래 범위로 단일 18·복수 2·주관식 5문항을 만든다.
5. 객관식·주관식에 각각 오답을 넣어 23/25점, 보류 0, 오답 2개를 확인한다.
6. 이전 범위의 오답을 요약하고 같은 개념의 변형을 만든다. 복습 기록 25개가 해당 목표에만 생긴다.

모의 에이전트는 계약과 저장 경계를 검증하기 위한 것이다. 실제 검색 결과·문항 품질·다양한 답안의 채점 정확성·실무 수행 능력을 증명하지 않는다. 기본 검사에는 실제 모델 호출이나 결제가 없다.

## 확장 기준

- 분야별 예외 코드를 추가하기 전에 입력 자료·목표 수준·범위·문항 유형·채점 기준으로 표현할 수 있는지 확인한다.
- 다음 검증은 분야 자체보다 자료 형태와 실패 조건을 넓힌다. 설명 자료, 기존 문제/정답표, 근거 부족, 범위 변경, 취소·재개를 우선한다.
- 현재 지원 범위는 텍스트·HTML·텍스트 PDF·선택한 언어의 스캔 PDF OCR, 단일/복수 선택·서술형·Python 표준입출력 실행 문제다. OCR은 원본 이미지 검토가 필요하고, 복잡한 수식의 의미·모든 라이브러리·실제 장비 동작을 자동 검증하지 않는다. 청해는 제외했다. 범용 목표 입력이 모든 학습 매체의 지원을 뜻하지 않는다.

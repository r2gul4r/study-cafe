# 실제 공개 시험 PDF 추출 검증 · 2026-10-15

이 문서는 텍스트 단계의 당시 결과다. 이후 그래프·수식·다중 페이지 정답 연결 개선과 실제 재검증은 [PDF 이미지 후속 검증](LIVE_PDF_VISUALS.md)을 참고한다.

기존 ChatGPT 관리 로그인의 Codex App Server로 실제 공개 시험 PDF와 별도 정답·해설 PDF를 수집하고 문항 추출·독립 검토를 실행했다. 제품의 `ingest_source`와 `extract_questions` 작업을 그대로 사용했고 기존 공부방과 분리한 임시 DB에서 진행했다. 추가 결제, API 키, 유료 OCR·검색·대체 공급자는 사용하지 않았다.

## 자료와 검증 범위

- [MIT 18.05 Spring 2022 시험 목록](https://ocw.mit.edu/courses/18-05-introduction-to-probability-and-statistics-spring-2022/pages/exams/)에서 연습시험과 별도로 게시된 **Exam 1**을 선택했다.
- [시험 PDF](https://ocw.mit.edu/courses/18-05-introduction-to-probability-and-statistics-spring-2022/mit18_05_s22_exam01.pdf): 11페이지. 행정 안내인 0번을 제외하면 큰 문제 6개이며 여러 소문항을 포함한다.
- [정답·해설 PDF](https://ocw.mit.edu/courses/18-05-introduction-to-probability-and-statistics-spring-2022/mit18_05_s22_exam01_sol.pdf): 6페이지. 단순 번호표가 아니라 풀이가 포함된 별도 문서다.
- 저자: Jeremy Orloff, Jennifer French Kamrin / MIT OpenCourseWare. [이용 안내](https://ocw.mit.edu/pages/privacy-and-terms-of-use/)의 CC BY-NC-SA 4.0 조건과 저자 표시를 유지하며 비상업적 로컬 검증에 사용했다. 원본 PDF·문제 전문·계정 정보·사용자 DB는 Git에 올리지 않는다.

URL·학습 범위·이용 근거를 검증 코드에서 미리 등록했다. 따라서 이번 결과는 **확인한 URL에서 실제 다운로드한 PDF의 추출 검증**이며, 자유 목표 입력부터의 자동 검색 성공이나 여러 시험 전체의 정확도 검증은 아니다. 영어 원문을 번역하지 않고 유지했다. 모델은 기존 설정을 사용했고 정확한 모델명은 기록하지 않았으며 추론 강도는 `medium`이다.

## 발견한 문제와 수정

1. **마지막 페이지의 판본 정보 누락.** 두 PDF의 `Spring 2022`는 마지막 저작권 페이지에 있었다. 기존 추출 요청은 표지만 공통으로 보내 첫 구간에서 같은 판본임을 입증하지 못했다. 이제 원문과 연결된 정답 자료의 앞·뒤 구간을 판본 확인용으로 전달한다. 문항 자체는 현재 처리 구간에서만 추출할 수 있고, 판본 근거 양쪽과 원문 인용 검사는 유지한다.
2. **과도한 PDF 좌표 입력.** 글자별 좌표를 본문과 함께 에이전트에 보내고 있었다. 시험 앞 3쪽·마지막 쪽·정답 6쪽의 같은 10구간 JSON을 비교하면 487,287바이트에서 17,353바이트로 감소했다(약 96.4%). 본문은 14,474자다. 좌표는 DB에 남기고 모델 입력에서만 제외하며 페이지·본문 오프셋은 유지한다. 이 수치는 동일 자료 배열의 직렬화 크기로, 모든 호출 토큰이나 응답 시간의 감소율은 아니다.
3. **인쇄되지 않은 합성 문항 번호.** 모델이 상위 번호와 소문항을 합쳐 `Problem 2. (a)` 같은 연결 키를 만들거나 정답 인용에서 번호를 빼는 응답을 냈다. 실제 인쇄된 `(a)`를 쓰고 상위 문제와 공통 지문도 근거에 포함하도록 명시했다. 번호가 같아 보인다는 이유만으로 통과시키지 않고 독립 검토에서 상위 문제·지문·정답을 대조한다.
4. **원문 수식·지문을 고쳐 쓰는 응답.** 문항·보기·지문을 공백 정리만 허용하는 연속 인용으로 제한한다는 점을 명시했다. 본문이 손상됐으면 답지에서 임의 복원하지 않고 미해결로 남기도록 했다. 원문 검사 자체는 완화하지 않았다.
5. **주관식 형식 오류의 불명확한 이유.** 모범답안, 빈 선택지/정답 배열, 기준 ID, 기준 배점 합계를 각각 설명하도록 오류 메시지를 나눴다. 형식 오류만 이전 오류를 전달해 한 번 보완하며, 제공자 제한·연결·시간 초과는 자동 내용 재시도하지 않는다.
6. **짧은 정답표 검색 누락 가능성.** 문제 본문의 용어가 없는 숫자·기호 위주 정답 구간도 제한된 남은 문맥에 채운다. 앞뒤 판본·관련 구간을 우선하고 최대 12개 구간으로 제한한다. 긴 정답표 전체가 항상 포함되는 방식은 아니다.
7. **많은 소문항을 한 번에 출력할 때 시간 초과.** 입력 좌표를 줄인 뒤에도 3페이지, 이후 한 페이지의 4개 소문항 출력에서 각각 240초 제한에 걸렸다. 추출 대상은 한 구간씩 처리하고 한 응답에 최대 2문항을 받는다. 남은 문항이 있으면 처리한 목록을 전달해 이어받고, 각 응답을 체크포인트에 저장한다. 앞뒤 구간은 이어지는 문제·공통 지문 문맥으로 유지한다. 진전 없는 반복이나 구간당 20회 한도에서는 남은 범위를 미해결로 표시한다. 시간 초과·제공자 오류는 자동 반복하지 않는다. 호출 수는 늘 수 있으며 복잡한 개별 문항의 시간 초과가 모두 해결된 것은 아니다.
8. **재추출 시 제목 유무만 다른 중복.** 같은 문제를 다시 추출할 때 공통 지문에 상위 제목을 포함했는지에 따라 두 문항으로 저장됐다. 같은 목표·범위·원문 구간의 유일한 동일 본문과 인쇄 번호가 일치하면 기존 문항을 재사용하고 저장된 답안을 덮어쓰지 않는다. 한 구간에 같은 본문이 여러 번 나오면 자동으로 합치지 않는다. 기존 실험에서 생긴 후보를 삭제해 결과를 꾸미지 않는다.
9. **같은 인용을 두 필드에 복사해야 하는 계약.** 실제 응답의 `sourceMatch`에는 정확한 연결 인용이 있지만 `evidence`에 동일 문장이 빠져 정상 후보 2개가 거부됐다. 이제 모델이 이미 반환한 연결 인용을 서버에서 근거 목록에 합친 뒤, 이번 요청에 제공한 원문과 문자 단위로 대조한다. 인용을 새로 만들거나 다른 자료를 검색해 채우지 않는다. 새 지시는 중복 출력을 요구하지 않아 응답도 줄일 수 있으나 이 마지막 프롬프트의 전체 새 실행 성능은 측정하지 않았다.

과목·시험명으로 분기하는 제품 코드는 추가하지 않았다. MIT 이름과 답안은 검증 자료에만 사용한다.

## 실제 결과

**학습 소문항 15개 중 11개가 사용 가능, 4개는 미해결**이다. 1(b)의 두 계산은 원문에서 하나의 소문항이므로 하나로 센다. 행정 안내인 0번은 학습 문항 수에 포함하지 않는다.

| 원문 문항        | 사용 가능 수 | 직접 대조한 내용                                                        |
| ---------------- | -----------: | ----------------------------------------------------------------------- |
| 1(b)             |            1 | 합집합 0.75, 조건부 확률 5/6                                            |
| 2(a), 2(b)       |            2 | 암호 수 `C(10,2) × C(8,5) × 20 × 10³ × 52⁵`, 기호 인접 확률 1/5         |
| 3(a)~3(d)        |            4 | 결합·주변확률표, 7/32, 5/7, 독립 아님                                   |
| 4                |            1 | 주어진 수치의 베이즈 계산 0.125                                         |
| 5(a), 5(b), 5(d) |            3 | 주변밀도 `5/4−x/2`, `5/4−y/2`; 독립 아님; 공분산 −5/576, 상관계수 −5/47 |

- 사용 가능한 11개는 모두 실제 Codex의 독립 검토를 받았다. 같은 목표·범위, `past_exam` 분류, 원문 문구, 인쇄 번호, 문제/정답 양쪽의 판본 근거, 정확한 인용을 저장 자료와 다시 대조했다. 2·3·5번의 공통 지문 묶음 ID도 유지됐다. 5(d)는 문제 7쪽과 앞쪽 공통 지문을 함께 읽어 통과했다.
- 전체 추출 작업은 재개 끝에 **9문항 사용 가능**으로 완료됐다. 이후 마지막 인용 병합 수정은 그 작업에서 받은 **원래 응답을 수정하지 않고 재생**해 3(a)·5(a)의 저장 검사를 통과시켰고, 실제 Codex의 새로운 독립 검토 2회로 추가 확인했다. 이것을 마지막 프롬프트로 PDF 전체를 새로 추출한 결과와 혼동하지 않는다. 원래 작업의 거부 기록과 추가 확인 기록을 모두 남겼다.
- 1(b)의 3+3점, 3(a)의 6+2+2점처럼 원문에 없는 세부 기준 배분은 학습용이며 공식 채점표가 아님을 해설에 표시했다. 명시한 총점·요구 출력만 따르고, 독립 여부를 묻는 문제에 별도 설명을 필수로 추가하지 않았다.
- 앞선 실패 실행에서 남은 후보 2개는 검토 대기로 보존했다. 최종 11개에 포함하지 않으며 사용자 공부방에도 가져오지 않았다.

| 1(a) | 분포 비교 그래프가 텍스트 입력에 없음                                                     |
| 5(c) | 해설의 `(c)` 표지는 3쪽, 답은 4쪽으로 분리되어 현재 단일 구간 연결 계약으로 입증하지 못함 |

## 실패 이력과 자동 검사

수집을 포함한 **11차례 실행·45회 호출 시도**다. 최종 결과가 저장된 호출은 44회로, 형식 성공 37회·형식 오류 2회·240초 시간 초과 5회다. 별도 1회는 좌표 입력 크기를 확인한 뒤 진행 중에 직접 중단했고 완료 응답·시간을 확보하지 못했다. 당시 스크립트는 완료 시 호출 수를 저장했으므로 세션 카운터 합은 44이며, 확인된 중단 1회를 별도로 더했다. 이후 호출 시작 시에도 카운터를 저장하도록 고쳤다. 형식 성공에는 미해결만 반환한 응답도 포함한다.

저장된 호출 시간 합은 **2,564.407초(약 42.7분)**이며 중단된 호출·수집·코드 수정 시간은 제외했다. 첫 실행은 판본 부족으로 사용 가능 문항이 0개였고, 이후에도 형식 오류와 시간 초과가 있었다. 분할 후에도 간헐적인 시간 초과가 남았지만 같은 작업의 미완료 단계부터 재개해 완료했다. 제공자 429나 계정 한도는 이번 PDF 실행에서는 관찰하지 않았다. 일반 앱의 기본 요청 제한은 180초, 이 진단 실행은 240초였으며 **시간 초과가 모두 해결됐다는 검증은 아니다.**

신규 자동 검사 9개를 포함해 **`pnpm check` 87/87·백엔드/프론트 타입 검사·`pnpm build` 통과**. 실제 PDF 인입, 마지막 페이지 판본, 인접 구간, 좌표 저장 보존/요청 제외, 번호·인용 병합, 고유 문항 재사용과 애매한 반복 본문 분리, 제한 재시도, 이어받기 실패/재개·무진전 중단을 확인했다. 일반 자동 검사에서는 실제 Codex를 호출하지 않는다.

기존 공부방에 패치를 적용한 뒤 **25문항·34/39점·보류 0개**가 유지되는 것을 확인했다. 원본 PDF와 전체 모델 응답은 격리 임시 폴더에만 보관한다. [근거 JSON](evidence/live-pdf-extraction-2026-10-15.json)에는 URL·PDF 해시·페이지·호출/실패·검토·인용 해시와 실제 응답 재검증 이력을 저장했다. 원자료에서 유래한 짧은 인용은 위 저자·이용 조건을 따른다.

## 원본 화면과 남는 한계

PDF를 로컬에서 렌더링해 그래프, 암호·주사위 문항, 페이지를 넘는 문제, 해설을 확인했다. 문제 5는 6~7쪽에 걸치며 공통 지문의 `5/4−xy`는 보존됐다. 반면 5(e)의 적분 첨자와 6번 감마분포의 분자·분모·지수 배치는 텍스트 순서에서 분리됐다. 독립 검토에 전달하는 현재 자료는 텍스트이며 PDF 원본 이미지 입력이나 수식 복원 기능을 구현한 것은 아니다.

해설 5쪽의 문제 6에는 합계 분산 계산이 `20 × 5 × 10^4 = 10^5`로 인쇄되어 있다. 왼쪽 계산은 `10^6`이며 같은 페이지의 표준편차와도 맞지 않는 **원본 오타**를 렌더링으로 확인했다. 자동으로 공식 해설을 고치거나 불확실한 문항을 정상 자료로 바꾸지 않는다.

스캔 OCR, 그래프·도형의 문항별 이미지 연결, 복잡한 수식·표의 읽기 순서 복원, 수십 페이지 정답표의 구간 검색, 다국어 판본·번호 체계는 별도 검증·개선이 필요하다. 이번 한 쌍의 PDF 결과로 해당 범위를 완료했다고 표시하지 않는다.

```powershell
# 인용 병합 수정 전의 실제 응답을 재생하고 새 Codex 독립 검토
pnpm exec tsx scripts/live-pdf-extraction.ts --live --phase=recheck --resume=<검증폴더>
```

- `pdf-report.json`에 검증 표식이 있는 폴더만 재개한다. 운영 DB를 지정하지 않는다. 원본 PDF·구간·모든 완료 호출의 출력과 실패 기록은 그 임시 폴더에 보관한다.
- `--new-extraction`은 이전 추출 이력을 남기고 수정된 코드로 새 작업을 만든다. 실행 중인 이전 작업이 있으면 거부한다. 일반 재개는 저장된 완료 단계를 다시 호출하지 않는다.
- 실행당 기본 최대 30회 호출이며 `--max-calls=N`은 1~100 범위다. 제공자 오류는 그 실행을 중단한다. 실제 호출은 기존 계정의 사용량을 소모한다.
- 이번 마지막 전체 작업의 재개에는 `--max-calls=40`, 추가 2문항 확인에는 `--max-calls=5`를 사용했다. `recheck`는 이미 성공한 작업의 실제 응답 중 인용 병합으로만 해결되는 후보에 한정하며, 답·인용 문구를 편집하지 않는다.
- 실행 파일을 찾지 못하면 `$env:CODEX_BIN = (Get-Command codex).Source`로 지정한다. 원본 웹 자료와 모델 응답이 달라질 수 있으므로 동일 결과를 보장하지 않는다.
- `audit`는 저장 근거의 구조 검사다. 정답의 의미·누락·수식 가독성을 사람처럼 모두 판단하는 정확도 검사가 아니며 실제 출력의 별도 대조가 필요하다.

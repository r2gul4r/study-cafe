# 공부 세션 모델·추론 설정과 바탕화면 실행

## 사용

**내 목표 → 목표 펼치기 → 이 목표의 AI 세션**에서 모델 메뉴와 추론 슬라이더를 사용한다. 모델 메뉴는 선택 항목에 체크를 표시하고, 슬라이더는 모델이 제공한 추론 단계 순서를 그대로 사용한다. 드래그를 놓거나 방향키로 변경하면 자동 저장하며, 회전 화살표로 모델 기본 추론 강도를 복원한다. 별도 적용 버튼은 없다. 학습 홈과 공통 상단에는 모델 선택창을 두지 않는다. 여기서 공부 세션은 목표별 전담 Codex 대화다. 모델을 바꿔도 학습 기록·대화 ID를 지우지 않는다.

- 선택 목록은 설치된 Codex의 `model/list` 모든 페이지에서 읽는다. 모델 ID나 추론 수준을 코드에 고정하지 않는다. 모델을 바꾸면 그 모델의 기본 추론 강도를 먼저 선택한다.
- 사용자 요청으로 Daybreak 계열은 공부방의 목록·선택 API에서 제외한다. 과거에 저장된 Daybreak 설정은 다른 모델을 선택한 뒤 AI 작업을 실행해야 한다. 현재 설치 기준 노출 모델은 7개이며 이전 8개 모델 검증은 제외 전 기록이다.
- 저장할 때 서버가 모델·추론 조합을 다시 검사한다. 알 수 없는 모델, 미지원 추론, 보관된 목표, 연결 실패는 기존 설정을 덮어쓰지 않는다.
- 아직 지정하지 않은 목표는 기존 환경 변수/Codex 기본 모델과 `medium` 동작을 유지한다. 목표별 선택이 환경 변수보다 우선한다.
- 실행 중인 호출은 시작할 때 선택한 설정으로 끝낸다. 저장 후 새로 시작하는 호출부터 반영하며, 같은 작업 안의 다음 호출도 새 설정을 사용한다. 이미 완료된 체크포인트는 재실행하지 않는다.
- 검증·채점·재채점은 같은 목표 설정을 사용하지만 각각 별도 임시 대화다. 전담 세션의 대화 이력을 전달하지 않는다. 실제 요청 설정은 작업 이벤트 `agent_configuration`에 기록한다.
- DB v4 `goal_agent_settings`에 저장하고 기존 v1~v3 백업도 이전한다. 목표 삭제 시 설정도 외래 키로 함께 삭제한다. 다른 PC에서는 해당 계정/설치가 같은 모델을 제공하는지 다시 확인해야 한다.

API: `GET/PUT /api/goals/:id/agent-settings`, `GET /api/agent/models`. 기존 인증·출처 검사를 그대로 거친다. 모델 목록에 등장하는 것만으로 추론 성공을 보장하지 않는다.

## 목표 내부 선택 UI 후속 검증 · 2026-10-18

### 실제 Codex 모델 연결과 선택 UI 재검증

- 앞선 브라우저 검증용 서버(4319)의 `UI test model (no AI)`는 실제 모델 목록이 아니다. 그 탭을 결과로 남겨 혼동이 발생했다. 실제 기본 공부방 서버(4317)를 시작하고 실제 로그인된 Codex `model/list`의 8개 모델을 확인했다. 테스트 서버에는 검증 전용 안내를 추가하고 검증 탭을 닫았다.
- 실제 공부방은 목표 0개였으며 `[확인용] Codex 모델·추론 선택` 목표를 만들어 8개 모델을 모두 화면에서 선택·저장했다. Astra의 Ultra, Luna의 Max, 기본값 Medium 복원, 마우스 드래그·방향키 변경, 재조회/새로고침 후 보존을 확인했다. 마지막 확인용 목표 설정은 GPT-6-Astra/high다.
- 데스크톱 1280px·모바일 390px에서 메뉴와 슬라이더를 확인했다. 모바일 문서 폭 375px로 가로 넘침 없음. 기존 텍스트 입력 스타일이 range 입력에 덮이던 현상도 수정했다.
- 실제 Codex 인증 상태·모델 목록만 조회했고 AI 추론은 실행하지 않았다. 모델 목록에서 노출·설정 저장된다는 사실과 실제 추론 성공은 구분한다. 이번에 모든 모델의 응답 품질·추론 성공을 검사한 것은 아니다.
- 웹 타입 검사·빌드와 설정·목표 세션 회귀 테스트 10개 통과. [실제 공부방 모델 메뉴·추론 슬라이더](evidence/codex-model-picker-2026-10-18.png). 목록/기본값/지원 단계는 [공식 model/list 규격](https://learn.chatgpt.com/docs/app-server#list-models-modellist)을 따른다.

### 이전 드롭다운 UI 검증

- 공통 상단의 선택창을 목표 상세 내부의 모델·추론 드롭다운으로 옮겼다. 저장 중 중복 변경을 막고, 응답 유실 등 저장 실패 시 재조회한 뒤 다시 편집하도록 안내한다.
- Chrome의 격리 DB에서 Python 목표 설정 변경·자동 저장 → 일본어 목표 기본값 유지 → Python 복귀·새로고침 후 선택 유지 → 모델 목록 새로고침을 확인했다. 390px 모바일과 1280px 데스크톱에서 선택창이 화면 안에 들어온다.
- 웹 타입 검사·웹 빌드, `tests/agent-settings.test.ts`와 `tests/goal-sessions.test.ts`의 **10개 회귀 검사 통과**. 기존 대화 ID 유지와 실행 중 변경의 다음 호출 적용은 모의 에이전트 검사다. 이번 UI 변경 검증에서는 실제 AI 추론·유료 API·디자인 크레딧을 사용하지 않았다.
- [목표 내부 설정 화면](evidence/goal-session-settings-2026-10-18.png). 아래 기존 실제 Codex 검증은 이전 선택창 구현 당시 기록이며 이번 실행과 구분한다.

## 바탕화면

`scripts/create-shortcut.ps1`는 현재 사용자의 실제 Desktop 폴더에 **공부방.lnk**를 만들고 저장소의 `scripts/launch.ps1` 및 `assets/study-cafe.ico`를 연결한다. 다른 목적의 같은 이름 바로가기를 덮어쓰지 않는다. 프로젝트를 이동했다면 같은 실행기 위치를 확인하고 바로가기를 다시 만들어야 한다.

실행기는 먼저 기존 서버를 확인하고 일회용 브라우저 연결로 연다. 꺼져 있으면 `start.ps1 -NoBrowser`를 숨김 프로세스로 실행해 준비된 뒤 브라우저를 연다. 중복 클릭은 실행기 뮤텍스로 직렬화하고 이미 켜진 서버를 재사용한다. 오류 알림과 `output/launcher` 로그를 제공한다. 브라우저를 닫아도 로컬 서버는 실행 상태를 유지한다.

아이콘은 앱 색상의 녹색 바탕·책·커피잔을 담은 SVG 원본으로 제작했다. `scripts/build-icon.mjs`가 16/24/32/48/64/128/256px PNG를 포함하는 ICO와 미리보기 PNG를 만든다. 웹 탭 favicon에도 같은 SVG를 사용한다.

## 검증 · 2026-10-18 KST

- 전체 자동 검사 **159/159**, 서버·웹 타입 검사와 빌드 통과. `checklist-vibe` CLI는 미설치로 생략하고 해당 스킬의 경계 검토 절차를 적용했다.
- 모델 목록 페이지 이동, 지원하지 않는 조합 거부, 인증 거부, 연결 실패 시 기존 선택 보존, 목표별 격리, 설정/세션 백업 복원·삭제, v3→v4 이전, 실행 중 설정 변경을 검사했다.
- 실제 Codex **2회**: GPT-6.1-Sol/low로 대화 시작 → DB·에이전트 종료 → 재시작 → GPT-6-Luna/high로 변경. 같은 thread ID에서 앞선 대화에만 있던 무작위 문구를 정확히 기억했다. 전체 모델·강도 조합의 품질 검사는 아니다.
- 실제 Chrome: 테스트 Python 목표에 GPT-6.1-Sol/high 저장 → 일본어 목표는 기존 기본 설정 유지 → 서버 실제 종료·실행기로 시작 → 새로고침 후 Python 설정 유지. 선택창 여백 누락을 화면에서 찾아 수정했다.
- 실행기: 켜진 테스트 서버 PID 재사용, 꺼진 상태에서 새 PID 시작을 확인했다. 바탕화면 `.lnk`를 생성 후 대상·인자·작업 폴더·ICO 경로를 다시 읽고, 실제 바로가기로 운영 공부방을 시작했다.
- 운영 공부방 백업 `352acf7a-bcf7-4d84-be23-2d630d1cce68` 후 적용. 실행 중 작업 0개 확인, DB v3→v4 이전 전후 기존 **33개 테이블 내용 해시 전부 동일**, 새 설정 테이블을 포함해 34개다.
- 검증 보조 스크립트에서 검색 인덱스에 없는 `rowid`로 정렬하던 오류가 있었다. 모든 행의 직렬화 내용을 정렬해 비교하도록 고쳤으며 제품 DB 오류와 구분한다. 기존 세션 테스트의 이벤트 기대값에 새 설정 이벤트를 반영한 뒤 전체 검사가 통과했다.

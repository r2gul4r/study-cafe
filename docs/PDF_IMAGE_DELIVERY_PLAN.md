# 다음 작업: PDF 이미지 선택 전달

상태: **설계만 완료, 제품에는 미적용**. 2026-10-15의 문항 영역 선택과 중복 텍스트 제거 다음 작업이다. 시험명·언어·특정 PDF에 따른 분기는 넣지 않는다.

## 현재 병목과 변경 지점

`src/workflows.ts`의 `extract_questions`는 문항 구간, 인접 구간, 판본 문맥, 검색한 정답 후보 전체에 `withPageImages`를 적용한다. `src/pdf-visuals.ts`의 `imageInputs`가 동일 자산을 합치지만 페이지 내용의 관련성을 골라내지는 않는다. 공개 PDF 재검증에서는 중복 텍스트를 1,689자 제거해도 이미지가 10개였다. 이미지 수가 많다는 사실만으로 시간 초과의 원인을 확정하지 않는다.

다음 구현은 원문 검색·저장을 그대로 두고 **한 호출에 실제 첨부하는 이미지**를 선택한다. `imageInputs`의 16개 제한을 유지하며, 텍스트 근거와 원본 PDF를 삭제하거나 낮은 해상도로 바꾸는 작업과 구분한다.

## 구현 순서

1. 순수한 이미지 전달 계획 함수를 분리한다. 입력은 문항 앵커, 인접 구간, 정답 검색의 `match` 구간, 판본 구간 및 명시적으로 요청한 구간이다. 반환값은 실제 첨부 페이지와 생략한 후보, 각각의 선택 이유다. 식별 키는 원본 판본 ID와 PDF 페이지 번호이며 같은 숫자의 다른 문서를 합치지 않는다.
2. 첫 요청에는 문항 앵커와 직접 매칭한 정답 페이지를 우선 넣는다. 인접 페이지와 판본 후보를 우선순위로 보충하되 초기 예산은 설정 가능한 상수로 둔다. 원문이 거의 없거나 수식/그림이 의심된다는 추정만으로 페이지를 영구 제외하지 않는다. 필요한 페이지를 모두 넣을 수 없으면 추가 요청 또는 미해결로 이어진다.
3. 생략한 페이지는 번호·자료·구간 ID의 탐색 목록으로만 제공한다. `latestMaterials`가 이미 캐시된 `pageImage`를 붙일 수 있으므로 **이번 호출에 첨부하지 않은 페이지의 `pageImage`는 요청 사본에서 제거**한다. 저장된 캐시는 유지한다. 이미지 ID가 있다는 이유로 실제 이미지를 본 것으로 취급하지 않는다.
4. 추출 응답에 `imageRequest`를 추가한다. `answerSearch`와 상호 배타적이며 요청 응답에는 문항/미해결 결과를 저장하지 않는다. 정답 원문 자체가 없으면 먼저 기존 `answerSearch`를 사용한다. 이미 전달한 원문에서 이미지가 부족하면 구간 ID로 페이지를 요청한다. 서버는 같은 목표·고정 판본·연결된 정답 자료의 허용 구간만 해석한다. URL, 로컬 파일 경로, 임의 자산 ID는 받지 않는다.
5. 추가 이미지 전달에서도 문항 앵커와 이미 찾은 핵심 정답을 유지한다. 요청을 반복해도 새로운 페이지가 없으면 중단하며, 최대 추가 회수와 전체 20회 응답 제한을 함께 적용한다. 16개를 넘는 필수 이미지가 생기면 조용히 자르지 말고 이유와 함께 미해결로 남긴다.
6. 이미지 요청/응답과 전달 페이지 ID를 체크포인트에 저장한다. 재개 때 동일한 페이지 집합을 복원하고 성공한 모델 호출은 반복하지 않는다. 범위나 원본 판본이 바뀌면 기존 추출과 섞지 않는다. 제공자 제한/연결 오류에 유료 대체나 무한 재시도를 추가하지 않는다.
7. 후보 저장 전에 `visualEvidence`의 이미지가 해당 추출 호출에서 실제 전달됐는지 검사한다. 독립 검토는 기존처럼 해당 문항의 모든 원본 근거와 학습자 표시 영역을 받고 원본 일치·완전성·정답 노출을 확인한다. 추출 입력량 최적화 때문에 검토 근거를 줄이지 않는다.

## 먼저 통과해야 할 검사

| 상황 | 기대 결과 |
| --- | --- |
| 긴 정답표 뒤쪽의 숫자 답 | 정답 원문·이미지를 함께 찾고 정확한 번호/판본 검사가 유지됨 |
| 정답이 다음 페이지로 이어짐 | 추가 페이지 요청 후 완전한 해설만 저장, 중간 페이지 생략 금지 |
| 판본 정보가 중간 페이지에 있음 | 판본 이미지를 요청해도 이미 찾은 정답 근거가 사라지지 않음 |
| 같은 페이지의 여러 텍스트 구간 | 이미지 한 번 전달, 모든 구간의 원본 연결 유지 |
| 다른 판본의 같은 페이지 번호 | 이미지와 인용을 서로 섞지 않음 |
| 캐시는 있지만 이번 요청에서 생략 | 이미지 ID를 본 것으로 허용하지 않고 필요 시 요청 |
| 다른 목표/정답 미연결 자료 요청 | 모델 호출 전에 거부하고 허용 범위를 확대하지 않음 |
| 같은 이미지 반복 요청·예산 초과 | 무한 호출 없이 이유를 남기고 미해결로 종료 |
| 추가 이미지 이후 제한·재개 | 성공한 호출을 반복하지 않고 같은 페이지 집합으로 복원 |
| 텍스트 자료와 기존 표시 영역 | PDF가 아닌 자료 경로와 독립 검토에 회귀 없음 |

실제 검증은 기존 공개 PDF의 정상 그래프·이어지는 해설과 새로운 분야 자료를 작은 묶음으로 실행한다. 첫 비교는 같은 원본·같은 문항의 전달 이미지 수, 픽셀 수/파일 크기, 원문 글자 수, 호출 수·시간, 독립 검토 결과를 기록한다. 제공자 사용량이 관측되지 않으면 토큰 절감률을 추정치로 발표하지 않는다. `usable` 비율만 높이려고 원본 오류·모호성 보류를 해제하지 않는다.

자동 문항 영역 추천은 이 작업 뒤의 별도 단계다. 현재 수동 표시 영역 선택과 원본 대조 검토를 재사용하되 모델이 제안한 영역을 기존 승인 문항에 자동 덮어쓰지 않는다.
